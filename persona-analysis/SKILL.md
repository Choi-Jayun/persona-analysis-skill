# 퍼소나 분석 (Persona Analysis)

이 스킬의 목적은 "그럴듯한 가상 인물 소개"가 아니라 **매출 의사결정에 쓸 수 있는 퍼소나**를 만드는 것이다. 마케터가 보고서를 받고 "그래서 다음 달에 누구에게, 어떤 채널로, 무슨 메시지를 던지면 되지?"에 바로 답할 수 있어야 한다. 그래서 모든 퍼소나는 실제 데이터(댓글 원문, 구매 수치, 설문 응답)에 뿌리를 두고, 근거가 약한 부분은 약하다고 밝힌다.

## 전체 흐름

1. **자료 점검** → 부족하면 먼저 요청 (아래 1단계)
2. **분석 모듈 A~E** 실행 (자료가 있는 모듈만, 순서대로)
3. **HTML 보고서** 작성 (`assets/report-template.html` 구조 사용)

분석 방법의 세부 기준(댓글 코딩 표, RFM 구간, 이탈 사유 분류, 기회 점수 공식)은 `references/methods.md`에 있다. 모듈을 시작하기 전에 해당 섹션을 읽는다.

---

## 1단계: 자료 점검과 요청

사용자는 자료가 부족하면 **분석 전에 먼저 요청받기를 원한다.** 추측으로 빈칸을 채운 보고서는 사내에서 그대로 인용되어 잘못된 의사결정으로 이어질 수 있기 때문이다.

받은 자료를 아래 표에 대조해, 각 모듈이 돌아갈 수 있는지 판단한다.

| 모듈 | 꼭 필요한 자료 | 있으면 좋은 자료 |
|---|---|---|
| A. 댓글 → 퍼소나 추출 | 댓글·리뷰 원문 (최소 30건 권장) | 작성일, 별점, 채널, 상품명 |
| B. 충성고객 퍼소나 | 고객ID별 주문 내역 (주문일·금액) | 연령·성별·지역, 유입채널, 재구매 고객 리뷰 |
| C. 브랜드 접점 | 유입채널/구매채널 정보 또는 "어디서 알게 됐나" 응답 | 채널별 매출, 광고 운영 채널 목록, 브랜드 URL |
| D. 비충성 고객 이유 | 1회 구매/이탈 고객 식별 가능한 주문 데이터 **또는** 비구매·이탈 설문/부정 리뷰 | 장바구니 이탈, 문의·CS 로그, 경쟁사 언급 |
| E. 매출 기회 퍼소나 | A~D 중 최소 2개 + 객단가·구매빈도를 알 수 있는 매출 데이터 | 마진, 마케팅 예산, 시즌성 |

표의 자료명은 예시다. 같은 역할을 하는 자료가 있으면 그것으로 대신하고 바로 진행한다. 설문 주관식 응답이나 인터뷰 메모는 댓글을 대신할 수 있고, 구독자 목록(가입일, 유지 개월, 상태)은 주문 내역을 대신할 수 있다. 형식이 다르다는 이유로 자료를 다시 요청하면 사용자는 같은 자료를 두 번 내게 된다.

판단 결과:

- **모든 모듈에 필요한 자료가 있으면** → 바로 분석으로 넘어간다.
- **빠진 자료가 있으면** → 분석을 시작하지 말고, 아래 형식으로 한 번에 요청하고 턴을 마친다. 받은 자료로 무엇이 이미 가능한지도 함께 알려줘야 사용자가 "그냥 이걸로 진행해"를 결정할 수 있다.

```
자료를 확인했어요. 지금 받은 자료로 가능한 것과, 추가로 있으면 좋은 자료를 정리했어요.

✅ 지금 가능: A. 댓글 → 퍼소나 추출 (댓글 84건)
⚠️ 자료 필요: B. 충성고객 / D. 비충성 고객 / E. 매출 기회

요청드릴 자료 (있는 것만 주셔도 돼요)
1. 주문 내역 CSV/엑셀 — 컬럼 예시: 주문일, 고객ID(익명 가능), 상품명, 결제금액, 유입채널
   → 충성/1회 구매 고객을 구분하고 객단가를 계산하는 데 씁니다
2. ...

자료가 없는 항목은 빼고 진행하거나, '가설'로 표시해서 진행할 수도 있어요. 어떻게 할까요?
```

요청 원칙:
- 왜 필요한지 한 줄씩 붙인다. 이유를 알아야 사용자가 대체 자료(예: 주문 데이터 대신 스마트스토어 통계 캡처)를 떠올릴 수 있다.
- 개인정보는 필요 없다고 분명히 한다. 고객ID는 익명 번호면 충분하다.
- 사용자가 "없어, 그냥 진행해"라고 하면 그 뜻을 따른다. 이때 자료 없이 만든 내용은 보고서에서 **가설** 배지를 달고, 검증 방법을 함께 적는다.
- 브랜드·상품 URL이 있으면 직접 읽어 상품 구성·가격·USP를 파악한다. 접근이 막히면 사용자에게 상세페이지 캡처나 소개 문구를 요청한다.

## 2단계: 분석 모듈

**먼저 데이터 품질부터 점검한다.** 분석에 들어가기 전에 자료끼리 맞지 않는 부분을 찾는다. 예를 들면 파일의 월 매출 합계와 브랜드 소개의 월 매출이 크게 다를 때, 쿠폰을 썼는데 정가로 결제된 주문, 가입일보다 유지 개월이 더 긴 행 같은 것이다. 찾은 내용은 '분석 자료와 방법' 섹션의 한계에 적는다. 표본 데이터라면 금액보다 비율 위주로 해석한다. 이런 점을 밝히지 않으면 금액이 실제와 동떨어져 보여 보고서 전체의 신뢰가 떨어진다.

각 모듈 시작 전에 `references/methods.md`의 해당 섹션을 읽는다. 데이터가 크면(댓글 수백 건, 주문 수천 행) 가능한 환경에서는 코드로 집계해 수치를 정확히 낸다. 눈대중으로 낸 비율은 틀리기 쉽고, 보고서의 신뢰를 한 번에 무너뜨린다.

### A. 댓글·리뷰 분석 → 퍼소나 추출
댓글 하나하나를 **상황(언제·왜 쓰나) / 욕구(Job) / 불만·장벽 / 감정 / 사용하는 말투·단어**로 코딩한 뒤, 비슷한 조합끼리 묶어 3~5개 퍼소나로 정리한다. 인구통계(나이·성별)는 댓글에서 직접 드러날 때만 쓰고, 드러나지 않으면 "추정"으로 표시한다. 각 퍼소나에 대표 댓글 원문 2~3개를 붙인다(닉네임은 가린다). 퍼소나별 댓글 건수와 비중을 반드시 적는다 — 이것이 "이 퍼소나가 얼마나 큰가"의 첫 근거다.

### B. 충성고객 퍼소나
주문 데이터로 RFM(최근성·빈도·금액) 구간을 나눠 충성고객을 **정의부터** 명확히 한다("최근 90일 내 구매 & 3회 이상" 등). 그 다음 충성고객 집단이 일반 고객과 무엇이 다른지 비교한다: 첫 구매 상품, 유입채널, 재구매 주기, 객단가, 그리고 이들이 남긴 리뷰의 언어. 충성고객이 "왜 계속 사는가"(지속 이유)와 "처음에 무엇에 끌렸나"(진입 계기)를 분리해 쓴다. 진입 계기가 신규 고객 확보 전략의 단서가 되기 때문이다.

### C. 브랜드 접점 (고객 여정)
인지 → 탐색·비교 → 구매 → 사용 → 재구매·추천 5단계로 고객이 브랜드를 만나는 채널과 순간을 정리한다. 퍼소나별로 주로 쓰는 접점이 다르면 퍼소나 × 단계 매트릭스로 보여준다. 각 접점에 "잘 되고 있음 / 끊김(이탈 지점)"을 표시하고, 끊김에는 근거(데이터 또는 댓글)를 단다.

### D. 비충성 고객 이유 분석
"선호도 없는 고객"을 세 부류로 나눠 본다 — **1회 구매 후 미재구매**, **재구매하다 이탈**, **관심은 있었지만 미구매**. 섞어 쓰면 원인이 뒤엉킨다. 원인은 `methods.md`의 장벽 분류(가격·가치 / 제품 적합성 / 신뢰 / 경험·서비스 / 인지·기억 / 대안·경쟁)로 코딩하고 비중을 낸다. 각 원인마다 "브랜드가 고칠 수 있는가"를 판정한다 — 고칠 수 없는 이탈(예: 타깃이 아닌 고객)에 예산을 쓰지 않게 하는 것이 이 모듈의 핵심 가치다.

### E. 매출을 올려줄 퍼소나 발굴
A~D에서 나온 퍼소나·세그먼트를 한 표에 올려 **기회 점수**(규모 × 구매력 × 전환 가능성 × 도달 용이성, 세부는 `methods.md`)로 순위를 매긴다. 상위 1~2개를 "우선 공략 퍼소나"로 선정하고 각각 다음을 적는다:
- 왜 이 퍼소나인가 (점수 근거 수치)
- 예상 매출 효과 — 계산식을 보여준다(예: 1회 구매 고객 420명 × 재구매 전환 10%p 개선 × 객단가 32,000원 ≈ 월 134만 원). 가정한 값은 가정이라고 밝힌다.
- 핵심 메시지 1문장, 채널, 오퍼, 첫 2주 실행안
- 성과 측정 지표(KPI)

신규 퍼소나(지금은 적지만 키울 가치가 있는 집단)와 기존 퍼소나 강화(충성고객 객단가 올리기 등)를 구분해 제안하면 사용자가 예산 배분을 판단하기 쉽다.

## 3단계: HTML 보고서

`assets/report-template.html`을 복사해 내용을 채운다. 템플릿의 CSS와 섹션 순서는 유지하고, 자료가 없어 생략한 모듈은 섹션을 지우는 대신 "자료 필요" 안내 박스로 남긴다(무엇이 빠졌는지 보고서만 보고도 알 수 있게).

보고서 구성:
1. **요약 (Executive Summary)** — 우선 공략 퍼소나 1~2개와 예상 효과, 핵심 발견 3가지. 바쁜 대표가 이 섹션만 읽어도 결정할 수 있어야 한다.
2. **분석 자료와 방법** — 사용한 자료(건수·기간), 정의(충성고객 기준 등), 한계
3. **A. 댓글 기반 퍼소나** — 퍼소나 카드
4. **B. 충성고객 퍼소나**
5. **C. 브랜드 접점 지도**
6. **D. 비충성 고객 이유**
7. **E. 매출 기회 퍼소나 & 실행안** — 기회 점수 표, 우선 퍼소나 실행 계획
8. **부록** — 코딩 결과 표, 가설 목록과 검증 방법

퍼소나 카드에는: 이름(별칭, 예: "성분 따지는 민감성 직장인"), 한 줄 정의, 규모(건수·비중·매출 비중), 상황·욕구·장벽, 대표 원문, 주요 접점, 공략 메시지를 넣는다. 사람 이름을 붙인 가상 인물 스토리("32세 김지은 씨는…")는 데이터보다 상상이 앞서 보이게 하므로, 꼭 필요하면 짧게만 쓴다.

근거 표시 규칙 — 보고서의 신뢰는 여기서 나온다:
- 수치와 원문 인용에는 출처(어떤 파일·몇 건 중)를 단다.
- 데이터로 확인된 주장은 그대로, 추론은 `<span class="badge hypo">가설</span>` 배지를 단다.
- 받은 자료에 없는 수치(시장 규모, 업계 평균 등)를 만들어내지 않는다. 필요하면 "업계 자료 확인 필요"로 남긴다.

파일명은 `persona-report-<브랜드명>.html`로 저장하고, 대화에는 요약(우선 퍼소나와 핵심 발견 3줄)과 파일 위치만 짧게 전달한다.
